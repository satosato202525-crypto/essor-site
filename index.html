01

新しい商品・サービスを形にしたい

アイデアを、「判断できる商品案」へ。

「こんな商品があれば」というアイデアだけでは、商品化には進めません。

誰に、どんな価値を届けるのか。顧客に選ばれそうか。自社で無理なくつくれるか。利益が残るか。

顧客ニーズ、商品コンセプト、原価、製造条件を一つずつ整理し、売れそう・つくれそう・利益が出そうを確かめながら、商品化までの道筋を組み立てます。

こんなときに

  • 新しい商品やサービスを考えている
  • アイデアはいくつもあるが、どれを進めるべきか決められない
  • 作ってみたいものはあるが、誰に売るのかが曖昧
  • 試作品はあるが、本当に顧客に選ばれるか確かめたい
  • 試作まではできたが、量産や採算に不安がある

実際に行うこと

  • 既存商品や新商品アイデアを整理し、取り組む優先順位を決める
  • 「誰に」「どんな価値を届けるか」を整理し、商品コンセプトを言語化する
  • 顧客価値・市場性と実現可能性の両面から商品案を比較する
  • 簡単な試作品やイメージを使い、顧客ヒアリング・アンケートの進め方を設計する
  • 自社商品や競合商品との比較から、改善すべき点を整理する
  • 技術・品質・生産体制・原材料調達など、量産前に確認すべき項目を洗い出す
  • 原価、限界利益、必要販売数を確認し、利益が残る条件を検討する

成果物の例

  • 商品コンセプト整理シート
  • 商品アイデア優先順位表
  • 顧客ヒアリング・アンケート設計
  • 競合・ベンチマーク比較表
  • 商品化・量産化チェックリスト
  • 試作から量産までの課題整理表
  • 原価・利益の簡易シミュレーション
  • 商品化までのアクションプラン

02

原価と価格を見直して、利益を残したい

「売れている」から、「儲かっている」へ。

売上が増えていても、利益が残っているとは限りません。材料費、人件費、エネルギー費、物流費などが上がれば、同じ価格で売り続けるほど利益が減ることもあります。

商品・取引ごとの採算を整理し、どこで利益が失われているのか、いくらで売れば必要な利益が残るのかを数字で確認します。価格改定が必要な場合は、その根拠も整理します。

こんなときに

  • 売上はあるのに利益が残らない
  • 原材料費や人件費の上昇を価格に転嫁できていない
  • 商品ごとの原価が分からない
  • 儲かっている商品・取引が分からない
  • 値上げしたいが、いくら上げるべきか判断できない
  • 取引先へ値上げの理由をうまく説明できない

実際に行うこと

  • 商品・製品ごとの売上、原価、利益を整理する
  • 企業間取引では、必要に応じて取引先別の採算まで確認する
  • 消費者向け販売では、必要に応じて販売チャネル別の採算まで確認する
  • 材料費、人件費、物流費など、利益を圧迫している要因を特定する
  • 限界利益と必要販売数を確認する
  • 現在価格と価格改定後の利益をシミュレーションする
  • 値上げの根拠となる数字を整理する
  • 原価低減と価格改定の両面から改善策を検討する

成果物の例

  • 商品・製品別採算表
  • 取引先別／販売チャネル別採算表
  • 原価構造の見える化資料
  • 利益改善シミュレーション
  • 価格改定シミュレーション
  • 値上げ根拠整理資料
  • 利益改善アクションプラン

03

現場のデータから、改善する場所を見つけたい

「忙しい」を、改善できる数字に変えます。

「忙しい」「時間がかかる」「効率が悪い」。現場で感じている問題も、数字にすると改善する場所が見えてきます。

作業時間、生産量、不良率、停止時間などを整理し、どこで時間・人・材料が失われているのかを見えるようにします。

必要に応じて、実際に作業時間を測ったり、動画を使って作業を分析したりします。

こんなときに

  • 現場は忙しいのに、生産性が上がらない
  • どの工程から改善すればよいか分からない
  • 作業時間にばらつきがある
  • データは取っているが、改善につながっていない
  • 改善した結果を数字で確認したい

実際に行うこと

  • 現場を確認し、「何を測れば問題が見えるか」を決める
  • 作業時間、生産量、不良、停止などのデータを整理する
  • 必要に応じて作業時間を測定する
  • 動画から作業や待ち時間を分析する
  • 工程ごとの時間やばらつきを比較する
  • ボトルネックやロスの大きい場所を特定する
  • 改善前後を比較する指標を決める

成果物の例

  • 現場データ分析レポート
  • 作業時間・サイクルタイム分析表
  • 工程別のロス一覧
  • グラフ・見える化資料
  • データ収集用フォーマット
  • 改善優先順位表
  • 改善効果の確認表

04

生産の流れを整えたい

「頑張って回す現場」から、「仕組みで回る現場」へ。

人によってやり方が違う。仕掛品がたまる。次の工程を待つ。忙しい人と手が空く人が同時にいる。こうした小さな詰まりが重なると、現場全体の生産性を下げます。

作業の流れ、時間、人員、設備、レイアウトを確認し、今ある人・設備・スペースを活かして、より無理なく流れる方法を考えます。

こんなときに

  • 人によって作業時間や品質に差がある
  • 工程間で待ちや滞留が発生している
  • 一部の工程だけいつも忙しい
  • 人を増やさずに生産量を増やしたい
  • レイアウトや作業方法を見直したい
  • 標準時間や標準作業を決めたい

実際に行うこと

  • 現場を歩き、モノ・人・情報の流れを確認する
  • 工程ごとの作業内容と時間を整理する
  • 待ち、運搬、仕掛品、手戻りなどを洗い出す
  • 工程間の能力差やボトルネックを確認する
  • 標準時間・標準作業の考え方を整理する
  • 人員配置や作業分担を検討する
  • 必要に応じてレイアウト変更案を作る
  • 改善項目に優先順位をつける

成果物の例

  • 工程フロー図
  • 作業・工程分析表
  • 標準時間一覧
  • ボトルネック分析
  • 改善優先順位表
  • レイアウト改善案
  • 改善実行計画

05

AIやデジタルツールを、仕事に使える形にしたい

「何ができるか」より、「どの仕事を楽にできるか」から考えます。

AIやデジタルツールは、導入すること自体が目的ではありません。

記録、転記、集計、資料作成、情報検索など、日々の仕事を見ながら、時間がかかっている作業や繰り返している作業を見つけます。

既製のサービスで十分なら、それを使います。ちょうどよいものがなければ、必要に応じて簡単なツールを作ることもできます。

こんなときに

  • AIに興味はあるが、自社で何に使えるか分からない
  • Excelや紙での集計作業に時間がかかっている
  • 同じ入力や転記を何度も繰り返している
  • 情報を探したり資料を作ったりする時間を減らしたい
  • 市販システムを入れるほどではないが、少し便利にしたい

実際に行うこと

  • 日々の業務を洗い出し、時間のかかっている作業を整理する
  • AI・自動化・既存ソフトで置き換えられる作業を選ぶ
  • 費用と効果を比べ、優先順位をつける
  • 小さな範囲で試し、実際の仕事で使えるか確認する
  • 必要に応じて簡単な集計ツールや業務用アプリを作成する
  • 導入後の使い方や運用方法まで整理する

成果物の例

  • 業務棚卸し・改善候補一覧
  • AI・デジタル活用マップ
  • 導入優先順位表
  • 簡易アプリ・集計ツール
  • 操作手順書
  • 導入前後の効果確認表

06

補助金も活用しながら、新しい取り組みを進めたい

補助金ありきではなく、「何を実現したいか」から考えます。

設備を入れたい。生産能力を上げたい。新しい取り組みを始めたい。まず整理するのは、「どの補助金を使うか」ではなく、何のために投資し、会社をどう良くしたいのかです。

投資の目的、費用、期待する効果、収益への影響、実施スケジュールを整理したうえで、活用できる公的支援制度があるかを検討します。

こんなときに

  • 設備投資を考えている
  • 新しい取り組みに使える支援制度を知りたい
  • 投資額に対して、どの程度の効果が必要か整理したい
  • 設備を入れたいが、投資の妥当性を判断できていない
  • やりたいことはあるが、計画として整理できていない

実際に行うこと

  • 現在の課題と投資の目的を整理する
  • 導入する設備・取り組みと期待する効果を整理する
  • 売上増加、原価低減、生産能力向上などの効果を数字で検討する
  • 投資額と収益への影響をシミュレーションする
  • 実施までのスケジュールを整理する
  • 活用可能性のある補助金・公的支援制度の情報を整理する
  • 必要に応じて行政書士などの専門家と連携する

成果物の例

  • 設備投資・事業計画整理シート
  • 投資効果シミュレーション
  • 収支・資金計画の整理資料
  • 実行スケジュール
  • 公的支援制度の比較整理表
  • 専門家へ引き継ぐための論点整理メモ

※ 官公署に提出する申請書類の作成・提出等については、法令に応じて行政書士などの専門家と連携して対応します。

07

研修・セミナーを依頼したい

現場の言葉で、伝わるまで話します。

改善活動を始めようとしても、共通の言葉がないまま進めると、途中で止まります。品質管理も生産管理も、まず「何を見ればよいか」が揃っていることが前提になります。

受講される方の経験や日々の業務に合わせて内容を組み、演習を入れながら、自社の現場に置き換えて考えられるところまで進めます。

こんなときに

  • 若手や中途入社の方に、品質管理の基礎を学ばせたい
  • QC検定の受験を社内で進めたい
  • 改善活動を始めたいが、共通の言葉がない
  • 現場でAIやデジタルツールを使えるようにしたい
  • 支援機関のセミナーとして登壇を依頼したい

テーマの例

  • QC検定3級対策
  • 現場改善の基礎（5S、ムダの見方、標準作業）
  • 品質管理の考え方と、記録の残し方
  • 現場で使えるAI・デジタルツールの活かし方
  • 開発と製造の間で、情報をどう受け渡すか

成果物の例

  • 研修資料
  • 演習シート
  • 受講後に現場で使えるチェックリスト
  • 理解度確認テスト

この経歴で何ができるか

開発と生産技術の両方を経験している診断士は、多くありません。

食品工場では一般に、開発と製造の間に断絶があります。開発は「この条件で作ってほしい」と言い、製造は「その条件では回らない」と言う。どちらも間違っていません。見ている時間の単位と、責任の範囲が違うだけです。

私は両方の席に座っていたので、双方の言い分がどちらも本当であることを知っています。その前提から、実際に回る条件を一緒に探すことができます。

Essor

屋号について

Essor（エソール）は、フランス語で「飛翔」を意味する言葉です。prendre son essor ——鳥が翼を広げ、羽ばたいて高度を上げていくこと。

食品工場の中には、値段に見合わないほどの技術が入っています。何度も試作を重ねてたどり着いた配合。一つずつ条件を詰めていった工程。書類にも数字にも残らないまま、担当者の手に蓄えられた判断。

けれどその中身は、買う人のところまで届いていないことがほとんどです。安く見られてしまうのは、技術が足りないからではありません。伝わっていないからです。

つくっているものの中身を、余すところなく伝えたい。それが、この仕事を選んだ理由です。

会社にも、翼を広げる瞬間があると思っています。新しい設備を入れる。新しい商品を出す。次の世代に引き継ぐ。そのときに必要なのは、飛び立つまでの助走です。

私は、その歩みに伴走し、企業が飛躍するサポートをします。
